\begin{abstract}
This report provides a comprehensive overview of the technology detection rules used by the Web Sites Analyser application. It documents the structure, organization, and coverage of 294 technology detection rules distributed across 14 YAML configuration files. The rules enable passive and active detection of web technologies, frameworks, services, and security configurations.
\end{abstract}

\section{Executive Summary}

The Web Sites Analyser utilizes a comprehensive rule-based detection system to identify technologies, frameworks, and services used by web applications. The project maintains a total of:

\begin{itemize}
    \item \textbf{294 technology rules}
    \item \textbf{14 YAML rule files}
    \item \textbf{2,630 total lines of configuration}
    \item \textbf{30+ evidence types} for detection
    \item Coverage across \textbf{Frontend, Backend, DevOps, Security, and Services} domains
\end{itemize}

\section{Rule Structure}

Each rule follows a consistent YAML structure:

\begin{lstlisting}[language=yaml]
- name: Technology Name
  category: Category
  version_pattern: 'optional regex pattern'
  evidence:
    - type: evidence_type
      name: optional_field_name
      pattern: 'regex pattern'
      confidence: 0.95
    - type: another_type
      confidence: 0.85
\end{lstlisting}

Key properties:

\begin{itemize}
    \item \textbf{name}: Human-readable technology name
    \item \textbf{category}: Technology classification
    \item \textbf{version\_pattern}: Optional regex for version extraction
    \item \textbf{evidence}: Array of detection rules
    \item \textbf{type}: Evidence type (header, cookie, script\_src, etc.)
    \item \textbf{pattern}: Regex pattern for matching
    \item \textbf{confidence}: Detection confidence (0.0-1.0)
\end{itemize}

\section{Usage Recommendations}

\subsection{For Analysts}
\begin{enumerate}
    \item Review confidence scores when interpreting results
    \item Combine multiple low-confidence detections for validation
    \item Use active detection mode for critical security assessments
\end{enumerate}

\subsection{For Developers}
\begin{enumerate}
    \item Add new rules to appropriate files based on category
    \item Ensure confidence scores reflect pattern specificity
    \item Include multiple evidence types for better accuracy
    \item Test rules against known technologies before deployment
\end{enumerate}

\subsection{For Operations}
\begin{enumerate}
    \item Regularly update rules for new technologies
    \item Monitor false positive rates per category
    \item Maintain separate rules for custom or proprietary technologies
\end{enumerate}
